Curriculum

BPF, eBPF and the eunomia-bpf projects

A chapter-wise guide: what the Berkeley Packet Filter and its extended form are, how they work inside the Linux kernel, and what every actively maintained eunomia-bpf project does, with diagrams, real code, papers and quizzes.

32 chaptersStart with Chapter 01 if eBPF is new to you

Part I · Foundations

01 · What is BPF? From packet filter to in-kernel VM

How a 1993 packet filter became Linux's safe in-kernel execution engine: classic BPF, seccomp-bpf, the 2014 eBPF rewrite, and a first hello world.

02 · The eBPF Instruction Set and Virtual Machine

The eBPF instruction set: eleven 64-bit registers, the calling convention, the 8-byte instruction format and its classes, atomics, BPF-to-BPF calls, the 512-byte stack, the interpreter and x86-64 JIT, constant blinding, and the RFC 9669 standard.

03 · The eBPF verifier

How the in-kernel verifier proves an eBPF program safe: the CFG pass, path-by-path abstract interpretation, register types, tnum and range tracking, pruning, precision, loops, limits, Spectre hardening, reading error messages, and the research that checks the verifier itself.

04 · Maps, helpers and kfuncs

How eBPF programs keep state in maps, stream events to user space through the ring buffer, and call into the kernel through stable helpers, unstable kfuncs, BPF-to-BPF calls and tail calls.

05 · Program types and hooks: where eBPF runs

Where eBPF programs attach — kprobes, trampolines, tracepoints, uprobes/USDT, perf sampling, LSM, cgroups, struct_ops, sched_ext, iterators and HID-BPF — and what each hook can see, change and cost.

06 · BTF, CO-RE and libbpf

How BTF type information, compiler-emitted CO-RE relocations and the libbpf loader let one compiled eBPF object run on many kernels, and how skeletons, links and pinning manage its lifecycle.

07 · eBPF in the networking stack: XDP, AF_XDP, tc/TCX and socket programs

Where eBPF hooks into the Linux packet path, from XDP in the NIC driver through AF_XDP, tc/TCX and socket-level programs, with real drop, redirect and tc programs and the commands to load them.

08 · The eBPF ecosystem map, and where eunomia-bpf fits

One exec tracer written in bpftrace, BCC, libbpf, cilium/ebpf, aya, libbpf-rs and eunomia-bpf; the major eBPF projects and runtimes; and a map of the eunomia-bpf organization that the rest of the curriculum follows.

Part II · Learning and tooling

09 · bpf-developer-tutorial: learning eBPF one small tool at a time

A guided tour of eunomia-bpf's bpf-developer-tutorial: how its 60-plus lessons are organized and built (ecc/ecli versus libbpf skeletons), how CI and the eunomia.dev site keep them current, six lessons read line by line, and a learning path mapped to this curriculum.

10 · eunomia-bpf: ecc and ecli

How eunomia-bpf's ecc compiler turns kernel-only eBPF C into a self-describing JSON package, and how ecli and bpf-loader-rs load it, derive a command line and print ring-buffer, perf or map data with no hand-written userspace code, plus Wasm, OCI, the GitHub template, the in-browser compiler and the Homebrew tap.

11 · Starter templates for libbpf and libbpf-rs

How eunomia-bpf's libbpf-starter-template (C) and libbpf-rs-starter-template (Rust) package a single libbpf-bootstrap-style app with submodules, vendored vmlinux.h, Docker, Nix and GitHub Actions, and how to turn one into your own project.

12 · wasm-bpf: eBPF user space in WebAssembly

How wasm-bpf moves the user-space half of an eBPF application into a WebAssembly sandbox: the seven host functions, how the Wasmtime and WAMR runtimes map them onto libbpf, how data crosses between linear memory, maps and ring buffers, and how the result is built, packaged as OCI images and run.

13 · bpf-compatible: CO-RE on kernels without BTF

How bpf-compatible trims BTFHub's kernel type files down to what one eBPF object needs, embeds them in the binary, and picks the right one at run time so CO-RE programs load on kernels without /sys/kernel/btf/vmlinux.

Part III · Userspace eBPF runtimes

14 · bpftime architecture: eBPF without the kernel round trip

How bpftime runs unmodified eBPF tools in userspace: the LD_PRELOAD syscall server, shared-memory maps, the injected agent, inline-hook uprobes, zpoline-style syscall hooks, the VM and verifier options, kernel interop, and the OSDI '25 EIM paper.

15 · bpftime in practice: running eBPF tools in userspace

How to install and drive bpftime: the load/start/attach/trace CLI, running unmodified libbpf tools (malloc, opensnoop, bashreadline, sslsniff, bpftrace) in userspace, bpftimetool, kernel-user mixed mode, CUDA kernel probes, XDP and nginx integrations, the repo's own benchmark numbers, and the current limits.

16 · llvmbpf: an LLVM JIT/AOT Compiler for eBPF

How llvmbpf lifts eBPF bytecode to LLVM IR instruction by instruction, JIT-compiles it with ORC, AOT-compiles it to native ELF objects, emits PTX and SPIR-V for GPUs, and serves as bpftime's default VM backend.

Part IV · Verifier, correctness and performance

17 · bpfix: explaining and fixing verifier errors

How bpfix turns a raw eBPF verifier log into a Rust-style diagnostic by reconstructing where the required proof was established and lost, how its 235-case empirical corpus and 75-task LLM repair benchmark were built, and what the measured repair gains are.

18 · ebpf-correctness-verifier: Translation Validation for eBPF Rewrites

How ebpf-tv checks that a rewritten eBPF object behaves like the original: translation validation, the K2-derived Z3 encoding of registers, memory, maps and helpers, the PASS/FAIL/UNKNOWN contract, a real test run, and measured gaps in the model.

19 · bpf-benchmark and bpfperf: Agent-Driven eBPF Optimization

How bpf-benchmark turns eBPF optimization into a closed-loop search for LLM agents over real applications, how its kinsn (BPF-Ext) modules give the kernel JIT verified native operations, how the bpfopt shim rewrites loaded bytecode on a stock kernel, and how bpfperf attributes LBR branch samples to BPF program counters.

Part V · eBPF for GPUs and accelerators

20 · gpu_ext: eBPF policies inside the GPU driver

How gpu_ext adds struct_ops hooks and kfuncs to NVIDIA's open UVM and RM driver so eBPF programs can choose GPU page prefetching, chunk eviction order and TSG timeslices, how its request-then-validate model keeps the driver in charge, how the device-side half (from eGPU, now in bpftime) runs eBPF inside CUDA kernels, and what the ASPLOS '27 paper and its artifact actually show.

21 · NCCLbpf: verified eBPF policies inside NCCL

How NCCLbpf runs verified eBPF policies inside NCCL's tuner, profiler and net plugins through bpftime, how a policy picks algorithm, protocol and channels for each collective, and why a load-time check must stop policies that let ranks disagree.

22 · xpu-perf: one flame graph for CPU and GPU

Profiling fundamentals (sampling, stack unwinding, symbolization, flame graphs), then how xpu-perf combines perf_event eBPF sampling from a fork of the OpenTelemetry eBPF profiler with a CUPTI injection library and a correlation-ID uprobe to draw CPU stacks and GPU kernel time in one flame graph, plus how it compares with Parca, Pyroscope, iaprof and Nsight.

Part VI · eBPF for AI agents

23 · AgentSight: system-level observability for AI agents

How AgentSight uses uprobes on TLS libraries and kernel tracepoints to watch an AI coding agent from outside, capturing what it asks the model and what it then does on the machine, and how a Rust pipeline of runners and analyzers joins the two streams into one timeline.

24 · ActPlane: information-flow enforcement for AI agents

How ActPlane compiles a small information-flow policy language into an eBPF/BPF-LSM engine that tracks labels across an agent's processes, files and sockets, and blocks, kills or explains rule violations.

25 · AgentCgroup: understanding and controlling the OS resources of AI agents

What a measurement study of 144 SWE-rebench tasks says about the CPU and memory behaviour of AI coding agents, and how AgentCgroup puts each tool call in its own cgroup and enforces priority with sched_ext and the proposed memcg_bpf_ops struct_ops.

26 · RewardGuard and safe change after external operations

How RewardGuard turns reward hacking in agent benchmarks into a runtime integrity contract enforced with AgentSight and ActPlane, and how agent-check-restore-safety keeps an external operation such as a payment from running twice or moving to a new destination when software is changed or restored.

27 · Actime and Akeep: one runtime for agent policy, observability and backup

How Actime composes the eBPF engines ActPlane and AgentSight with the Akeep session-history backup into one command and one run record, how Akeep stores agent transcripts in a content-addressed, optionally age-encrypted archive, and which of these parts actually use eBPF.

Part VII · Kernel extension research

28 · namei_ext: programmable VFS name resolution

How namei_ext adds a cgroup-scoped eBPF hook to Linux pathname lookup and readdir so a policy can pass, rename, hide, or swap in an existing object, while the VFS and the real filesystem keep handling everything else.

29 · qwen3-ebpf: a language model forward pass inside eBPF

How qwen3-ebpf runs all 28 decoder layers of Qwen3-0.6B as verifier-accepted BPF programs (fixed-point matmuls, bpf_loop batches, a BPF KV cache, BF16 weights in a BPF arena, XDP plus a BPF workqueue) and what its measurements say about the limits of eBPF as a compute engine.

30 · LLM agents for the kernel: schedcp, MCPtrace, GPTtrace

How the eunomia-bpf LLM-for-kernel line works: the Model Context Protocol, schedcp's MCP server that lets an agent pick, tune and write sched_ext schedulers (and its arXiv paper), MCPtrace's bpftrace tools, GPTtrace's prompt-and-retry pipeline, and the Kgent paper behind them.
